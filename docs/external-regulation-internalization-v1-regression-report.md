## 1. 结论速览

- 四个下游 Agent 全部真实可运行（非 Mock），均产出结构化 JSON + 文件运行目录 + 审计日志 + SQLite 索引，并可生成 HTML/Word/Excel/JSON/Markdown 交付物。
- 护栏有效：内容不对齐时模型不编造内规条款（输出「无匹配 / review_required」）；内容对齐时能产出真实映射。
- **V1 暂无法在数值上复现邮储托管历史报告**，根因是本机缺少与托管外规内容对齐的「邮储托管内规源文件」——仓库内只有邮储**输出 HTML 报告**，没有作为输入的 16 份托管制度源文件。邮储 HTML 因此仍只能作为 `demo-replay` 历史基准。

## 3. 与邮储历史报告基准对比

邮储历史基准（`docs/邮储银行托管业务制度合规对标映射报告(1).html`、`…差距分析报告(1).html`，`demo-replay` 只读）：

| 维度 | 邮储历史基准 | V1 本次（§2.1 跨境放款链路） | 比对结论 |
|---|---|---|---|
| 外规 | 《商业银行托管业务监督管理办法(试行)》五章 49 条 | 《境内企业境外放款管理办法》32 条 | **不同外规**（托管内规源缺失，改用可获取的真实外规） |
| 内规 | 邮储 16 份托管制度（14 份全文） | 1 份香港个人信贷制度（277 切片） | **不同内规**（无邮储托管内规源文件） |
| 合规分布 | 合规 24%(12) / 部分合规 49%(24) / 不合规缺失 27%(13) | 满足 0 / 部分满足 0 / 未满足 32 | **不可直接比对**（文档不对齐，全未满足为真实结论） |
| 风险分布 | 高 8 / 中 12 / 低 5 | 高 7 / 中 18 / 低 7 | 量级相近，但样本不同 |
| Gap 类型 | 制度型 / 执行型 5 / 混合型 3 | 制度型 32 | V1 全制度型（因内规完全未覆盖该外规领域，合理） |

### 3.1 一致的结论
- 风险分级三档（高/中/低）口径一致，分布量级接近。
- Gap 三分类（制度型/执行型/混合型）口径一致。
- 「未满足/缺失 → 制度型 Gap → 新增制度草案」的推理链一致。

### 3.2 不同的结论
- 合规率与满足度分布完全不同：邮储基准 24%/49%/27%，V1 为 0/0/100%。原因是输入文档不对齐，并非引擎问题（§2.2 已用对齐用例证明引擎可产出 53% 覆盖）。
- 邮储基准存在「执行型/混合型」Gap；V1 主链路全为制度型，因内规对该外规零覆盖。

### 3.3 需人工确认的结果
- §2.1 全部 32 条 Gap 与 12 条整改草案均默认 `needsReview`；制度草案须经法律合规部门审查。
- §2.2 中 18 条 review_required 映射需人工确认或排除。

### 3.4 因 V1 能力不足暂无法产出的字段
- BGE 语义信号未启用（缺 sentence-transformers / BGE 模型）：V1 候选筛选仅用 BM25 + 关键词，可能漏召回语义相近但词面不同的内规条款。
- 制度映射源文档要求的「恒丰 2,283 条内规标签体系 + COSO 五信号融合」：V1 未接入 taxonomy 与 COSO/处罚加权信号，仅做条款级候选 + LLM 复核。
- 上位法依据、修订历史、司法实践（北大法网 MCP 增强）：监管解读保留字段但未接入外部检索，多为空。
- 邮储托管 49 条 × 16 份制度的复现：缺源内规文件，无法产出。
